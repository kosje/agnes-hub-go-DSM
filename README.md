# agnes-hub-go

Agnes AI 的**多账号聚合中转 + RPM 限流排队网关**。

一句话说明它解决什么：把「20 RPM 硬墙 → 弹超限提示 → 无人值守任务断线」
变成「**网关自己排队等候，客户端永远拿不到 429**」，并把多个独立账号聚合成
线性可扩容的池，按模态（文本 / 生图 / 生视频）分工承载各自的 RPM。

客户端只需要填一个模型名 `agnes-auto`，其余全部交给网关。

- 纯 Go 标准库实现，**零第三方依赖**（规避代理被墙与供应链风险）
- 单文件可执行程序，无运行时依赖，可直接交叉编译到飞牛 NAS
- 跨平台运行期数据：全 JSON 文件，免 SSH 即可备份 / 迁移

## 1. 快速开始（Windows）

双击 `agnes-hub-go.bat` 即可。

脚本会做三件事：先检查端口是否被占用 → 没有 `agnes-hub-go.exe` 就尝试用本机
Go 编译 → 以前台方式启动服务。**关闭窗口即停止服务**，不注册服务、不设开机自启。

> **端口冲突提示**：默认端口 `4142` 与早期 Python 版 agnes-hub 相同（便于直接
> 切换，客户端配置不用改）。若该端口已被占用，bat 会打印出占用记录并给出两条
> 处理办法，而不是抛出一句难懂的系统英文错误。

首次启动后打开控制台 <http://127.0.0.1:4142/console>，初始密码 `admin123`，
**请立即修改**。然后在「账号池」里添加你的 Agnes 账号：

| 字段 | 说明 |
| --- | --- |
| 账号名称 | 自定义，支持中文（网关会自动做 latin-1 头转义） |
| API Key | 上游 Agnes 的 key |
| 账号类型 | `free` / `enterprise` / `tokenplan`，决定各池的基线 RPM |
| 上游地址 | 默认 `https://apihub.agnes-ai.com/v1`，中国站填 `https://api.agnes-ai.cn/v1` |
| 模型清单 | **按模态分组**声明该 key 真实可调用的模型，见第 4 节 |

再从「密钥」Tab 签发一把下游密钥，就可以按第 3 节的方式接入了。

## 2. 目录结构

```
agnes-hub-go/
├── main.go                     入口：标志解析、优雅关闭、启动横幅
├── agnes-hub-go.bat            Windows 一键启动（GBK + CRLF 编码，中文 cmd 必需）
├── internal/
│   ├── config/                 全部持久化状态（JSON 原子写、密码、密钥、任务映射）
│   ├── pool/                   模型名 → 池分类（限流桶）、模态 ↔ 池 换算
│   ├── pacer/                  FIFO 严格节拍器（限流正确性的根）
│   ├── hub/                    调度核心：候选筛选、粘性溢出、熔断、二维校准
│   ├── relay/                  转发层：排队、重试、换账号、响应回译
│   ├── intent/                 agnes-auto 意图判定与请求/响应适配
│   └── web/                    HTTP 层 + 内嵌控制台单页
│       └── static/console.html
├── tools/
│   ├── bat_src.utf8            bat 的 UTF-8 源码（要改启动脚本请改这个）
│   ├── make_bat.py             生成 GBK + CRLF 的 agnes-hub-go.bat
│   ├── check_bat.py            实测 bat 的编码与三个分支（不启动服务）
│   └── smoke_test.py           零配额端到端冒烟（不碰上游）
└── data/                       运行期数据（首次启动自动创建，勿提交）
```

### 修改启动脚本的正确姿势

中文 Windows 的 cmd 按 **GBK** 逐行解析 `.bat`。若文件是 UTF-8，含中文的行会被
字节错位切分，报 `'xxx' is not recognized as an internal or external command`，
并破坏 `if (...)` 复合块的括号配对 —— 本该跳过的分支反而被执行。

所以：**不要直接编辑 `agnes-hub-go.bat`**（编辑类工具默认写 UTF-8 + LF），
而是改 `tools/bat_src.utf8`，然后：

```bash
python tools/make_bat.py      # 生成 GBK + CRLF 的 bat，自带编码自检
python tools/check_bat.py     # 实测三个分支：直达 RUN / 无 go / 端口被占用
```

## 3. 客户端接入

任何 OpenAI 兼容客户端都可直接使用：

```
Base URL   http://127.0.0.1:4142/v1
API Key    控制台「密钥」Tab 里签发的那把 sk-agnes-xxxx
Model      agnes-auto
```

- 想要局域网内其它机器也能用，把 bat 里的 `HOST` 改成 `0.0.0.0`
  （或 `set AGNES_HUB_HOST=0.0.0.0`）。**此时务必先改掉初始密码**。
- 也可以直接指定具体模型名（如 `agnes-image-2.5-flash`）绕过自动判定，
  网关会尊重显式模型，绝不用内容判定去覆盖它。

### 接口一览

| 端点 | 用途 |
| --- | --- |
| `POST /v1/chat/completions` | 主入口，三模态都走这里；支持 `stream=true`（SSE） |
| `POST /v1/responses`、`POST /v1/messages` | 兼容 Anthropic / Responses 形态 |
| `POST /v1/images/generations` | 显式生图端点（端点即意图） |
| `POST /v1/videos` | 显式生视频提交（异步任务） |
| `GET /v1/videos/{job_id}` | 轮询视频任务；下游只见 job_id，网关负责映射上游 video_id |
| `GET /agnesapi` | /v1 双斜杠坑的兼容入口 |
| `GET /v1/models` | 模型目录（含 `agnes-auto` 与全部已知模型 + 别名） |
| `POST /v1/intent/preview` | **干跑**：只判模态、不调上游、不消耗配额 |
| `GET /healthz` | 健康检查 |

## 4. 多账号调配：按模态分工

这是本网关相比「单 key 转发脚本」的核心增量。上游一个 key 往往只买了某一种
模态的额度，而**限流是按模型类型分桶的**（官方限流表更新 2026-06-28）：

| 池分类 | free | enterprise | tokenplan |
| --- | --- | --- | --- |
| `text` | 20 | 40 | 1000 |
| `image_1k` / `image_2k` | 20 / 10 | 40 / 20 | 100 / 80 |
| `image_3k` / `image_4k` | 1 / 1 | 1 / 1 | 1 / 1 |
| `video` | 1 | 2 | 5 |

### 模型清单（model_manifest）的语义

控制台里每个账号都按模态填三份清单，**空数组与不填是不一样的**：

| 取值 | 含义 | 调度行为 |
| --- | --- | --- |
| 留空不填（`nil`） | 还没声明 | 用设置里的默认清单补齐 |
| 填了内容 | 真实可调用 | 该模态可用，且只从这里挑模型 |
| 显式清空成 `[]` | **明示不支持该模态** | 该账号被排除出对应池 |

最后一条是多账号分工的落点。把「只买了文本额度的 key」的 `image`/`video`
清空，生图请求就绝不会打到它上面去换回一个 403，也不会因为累计错误被熔断。

### 账号级 RPM 覆盖

`rpm_overrides` 优先于档位表。实测 Agnes 中国站 22 RPM（间隔 2.73s）可通过，
而 30 RPM（间隔 2.0s）第 2 个请求即被限 —— 官方文档的 20 RPM 并不是精确边界。
某个账号实际额度与文档不符时，就在这里覆盖，不必改代码。

### 批量操作

- 「批量导入」：一次粘贴多行 `名称,APIKey[,类型[,上游地址]]`
- 「批量更新」：按分组批量改账号类型 / 启用状态 / 模型清单
- 「一键探测」：并发探测所有账号，并做 **drift 检测**（账号声明的清单与上游
  真实返回不一致时标出来），避免「声明了但上游根本没有这个模型」

## 5. 限流机制

### 5.1 FIFO 严格节拍，而不是令牌桶 / 固定窗口

实测依据：22 RPM（间隔 2.73s）7/7 通过，30 RPM（间隔 2.0s）第 2 个即被限。
说明上游约束是「**相邻两次请求的间隔**」，而不是「60 秒窗口内的计数」。

因此：

- 令牌桶**不合格** —— 它允许突发，而突发恰好最容易命中「短时间内重复请求」判定；
- 固定窗口**不合格** —— 窗口边界会双倍穿透（第 59 秒与第 61 秒各打满一轮）。

网关采用 FIFO 严格节拍：相邻两次放行间隔 = `窗口 / 有效 RPM`，并发请求被
串行摊到节拍上。**准入判定在领号之前完成**，等不起的请求直接拒绝且不占用槽位
（若先领号再报超时，会出现「什么都没发出去、额度却没了」）。

### 5.2 二维自适应校准（账号 × 池）

上游真的返回 429，说明我们高估了边界，于是下调**该账号该池**的因子
（默认 ×0.8，下限 0.5），成功累计到阈值后再逐步回升（默认 +0.05 / 20 次成功）。

两个关键点：

1. **只下调出问题的那一个池**。文本池与视频池互不牵连 —— 视频池只有 1 RPM、
   最容易 429，若惩罚被写到账号级系数上，一次视频限流会把文本池一起砍掉 20%，
   表现为「配了多账号，文本却一起变慢」。
2. **按成功次数回升，而不是按墙钟**。低流量账号的墙钟回升永远等不到，
   表现为「校准砍下去就再也回不来」。

因子批量落盘（30s 一次），429 时也会立即写一次，保证进程重启后校准不丢。

### 5.3 软粘性 + 溢出

同一任务的多轮对话应落在同一个账号上（上下文一致），但绑定不等于钉死：

- 绑定账号**健康且不拥堵**（预计等待 ≤ 3s）→ 继续用它；
- 绑定账号拥堵或冷却 → 自动改派到预计等待最短的账号，**并把绑定就地更新**。

若命中绑定就无条件返回，客户端又默认不发会话头，就会出现「配了 5 个账号
实际只有 1 个在工作」。

### 5.4 并发信号量按模态分离

文本 / 生图 / 生视频各一把信号量（默认 8 / 4 / 2）。视频是异步任务、要反复
轮询，若和文本共用一把信号量，就会出现「一提交视频，聊天就卡住」。

### 5.5 熔断与自动复活

- `401 / 403 / 402`（凭证失效、额度耗尽）**不可重试**：立即熔断停用该账号，
  默认 30 分钟后自动复活并**低速试探**（保留已下调的校准系数，避免复活瞬间再撞一次）。
- `429`：只换账号重试，**绝不透传给客户端**。
- 生图与视频的**提交**是非幂等的：遇 5xx 不重试，避免重复扣费；
  查任务 / 轮询这类幂等请求才重试。
- 全员冷却时**不退化为报错**，而是等最早解冻的那个 —— 无人值守场景下
  「等一下」远好于「任务断掉」。

## 6. agnes-auto：一个模型名走全模态

上游并不存在「一个模型名走全模态」：把 `agnes-auto` 直接发给
`/v1/images/generations`，上游会回「模型 agnes-auto 是 chat 模型，
请使用 /v1/chat/completions」。所以这件事必须由网关做：判定模态 → 换成真实模型 →
必要时改写端点与请求体 → 再把响应翻译回 chat 形态。

判定信号，可信度从高到低：

| # | 信号 | 说明 |
| --- | --- | --- |
| 1 | 端点 | 打到 `/v1/images/generations`、`/v1/videos`。**端点即意图**，可压过一切 |
| 2 | 模型名 | 客户端给了具体模型名，按模型名归类，绝不覆盖 |
| 3 | 请求参数 | `size`/`aspect_ratio`（图）或 `num_frames`/`duration`（视频） |
| 4 | 内容语义 | 从用户那句话里读祈使式生成意图（唯一有误判风险的一条） |
| 5 | 默认回落 | 保守回落 `text` |

第 4 条只在前三条都不明确时启用，并且：

- 用「动词 + 名词」结构匹配，不用单词匹配；
- 元讨论 / 疑问 / 代码块 / 教学措辞一律扣分（「如何画一只猫」不会生图）；
- agent 类请求（含 `tools` / `tool_calls` / `response_format`）**直接禁用**内容判定；
- 必须越过阈值（默认 0.6）才切换；
- **产物归属判定**：中文件里产物几乎总在句末，谁的模态名词更靠后谁就是产物。
  「生成一段视频里的关键帧**图片**」→ 图片；「把这张**照片**做成视频」→ 视频。

误判代价不对称：把提问当生图，用户会收到一张莫名其妙的图。所以阈值偏高，
并且每次判定的 `source / score / reason` 都会写进响应头、响应体与日志，
事后可追查。想先验证判定结果而不消耗配额，用 `/v1/intent/preview` 干跑。

## 7. 编译

```bash
# Windows
go build -trimpath -ldflags "-s -w" -o agnes-hub-go.exe .

# 飞牛 NAS（x86_64）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o agnes-hub-go-linux-amd64 .

# 飞牛 NAS（arm64，如 N100 之外的 ARM 机型）
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o agnes-hub-go-linux-arm64 .
```

`go.mod` 刻意声明 `go 1.22` 而不是本机工具链版本：本项目零依赖、未使用
1.23+ 语言特性，而 1.22 是「`ServeMux` 支持 `/v1/videos/{id}` 路径参数」的
最低版本。声明得过新会让飞牛 / CI 上更常见的 1.22~1.24 工具链直接拒绝构建。

### 命令行标志

| 标志 | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `-host` | `AGNES_HUB_HOST` | `127.0.0.1` | `0.0.0.0` 表示允许局域网访问 |
| `-port` | `AGNES_HUB_PORT` | `4142` | 监听端口 |
| `-data` | `AGNES_HUB_DATA` | 可执行文件旁的 `data` | 数据目录 |
| `-version` | — | — | 打印版本后退出 |

## 8. 运行期数据

全部在 `-data` 指定的目录里，都是 JSON，可随时备份 / 拷贝 / 手工编辑：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 全局设置（安全系数、节拍窗口、校准参数、排队上限……） |
| `accounts.json` | 账号池（**含上游 API Key，注意保密**） |
| `downstream_keys.json` | 签发给客户端的密钥与用量 |
| `bindings.json` | 粘性绑定（会话 → 账号） |
| `video_jobs.json` | 下游 job_id ↔ 上游 video_id ↔ 承载账号的映射 |
| `usage.jsonl` | 用量日志（JSONL，控制台「日志」Tab 展示） |

写入一律走「临时文件 + rename」原子写，断电不会写坏配置；配置文件损坏时
会被备份成 `*.broken` 并按默认值继续启动，**不会让服务起不来**。

## 9. 验证

```bash
go test ./... -count=1
```

- `internal/pacer`：节拍间隔、并发串行化、拒绝不占槽位、调参夹紧积压
- `internal/hub`：按模态分工、模型清单边界、软粘性溢出、**二维校准的池间隔离**、
  熔断自动复活、并发信号量分离、排队超时
- `internal/config`：`nil` 与空数组语义（含 JSON 往返）、坏配置容错、原子写、
  密钥配额、跨天滚动、绑定 TTL 清理
- `internal/intent`：意图判定回归矩阵（正例 + 反例）、端点/模型/参数信号优先级、
  agent 守卫、请求体改写
- `internal/web`：起 mock 上游做端到端（**验证 429 永不透传**、三模态路由、
  多账号分工、中文账号名）

另外两个脚本（不消耗任何上游配额）：

```bash
python tools/make_bat.py      # 由 tools/bat_src.utf8 生成 GBK + CRLF 的 bat
python tools/check_bat.py     # 实测 bat 的编码与分支，断言不出现 "not recognized"
python tools/smoke_test.py    # 启动真实进程，走完整 HTTP 链路，不碰上游
```

`smoke_test.py` 覆盖的是「只有真正跑起来才会暴露」的那一层：进程启动、
控制台登录与 Cookie 会话、未授权访问被拒、签发下游密钥、账号池按模态分工的
落盘与回读、`agnes-auto` 干跑判定、无可用账号时返回 503 而不是硬闯上游，
以及退出后端口是否真的释放。

## 10. 已知边界与后续
