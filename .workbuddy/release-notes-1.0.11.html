一、本次新增能力

  • 多上游支持：账号类型新增 amd（developer.amd.com.cn/radeon）与 openrouter，不再局限于 agnes 通道。实测 AMD MiniCPM5-2B / Qwen3.8-27B 经网关返回真实完成体。
  • 完整编辑弹窗：控制台点击「编辑账号」弹出完整表单，可修改添加时的所有字段（名称、API Key、base_url、text/image 模型清单、优先级、RPM 上限）。
  • 按账号 RPM：每个账号可单独设置 RPM 上限，不再统一套用 agnes 的 20rpm；未设置时回退默认值。
  • 账号调用优先级：调度器按 priority → 区域匹配 → 等待时长 → 在飞请求数 选号，高优先级优先承接请求。
  • chat UI 支持非 agnes 模型：/chat 网页界面可下拉已添加的全部模型（含 AMD / OpenRouter），一键验证连通性。

二、两个关键修复（务必了解）

① AMD 经网关返回 {} 根因在 relay 层：attemptOnce 的 defer cancel() 与 defer resp.Body.Close() 在调用方读取上游响应体之前就触发，连接被提前关闭 / context 被取消，读到空体。 已改为：调用方读毕 body 后才 cancel() 并关闭（成功路径用 releaseOnClose）。 该 bug 影响所有上游（含 agnes，偶发空体），AMD 因响应体大被显式发现。
② 软粘性会话绑定错发模型 chat 请求因无下游 key / 无 x-session-id，SessionKey 恒为 "key:"，所有 chat 请求共享同一绑定。原 Pick 只按粘性选号、不校验本次 requiredModel：先用 AMD 模型把绑定钉到 amd1 后，再请求 agnes-2.5-flash / auto 仍错发 amd1（404/400）。 已在绑定判定加守卫：绑定账号不能服务本次具体模型时放弃旧绑定，按 requiredModel 重选。
③ E2E 验证通过 共享会话最坏情况：MiniCPM5-2B → amd1 绑定后，agnes-2.5-flash 仍正确命中 agnes 账号；家族内粘性正常，MiniCPM5-2B 再次正确回到 amd1。

五、配置要点

  • AMD 账号：类型 amd，base_url=https://developer.amd.com.cn/radeon/api/v1，模型如 MiniCPM5-2B、Qwen3.8-27B。网关会自动剥离尾部 /v1 拼接为 .../api/v1/chat/completions。
  • OpenRouter 账号：类型 openrouter，按 OpenRouter 模型名填写。
  • 每账号独立：可设 rpm_override（RPM 上限）与 priority（调度优先级）。
  • 多账号买到的是吞吐不是延迟：并发批量任务才能线性提速，单请求串行任务加速比约为 1.00x。

六、已知限制 / 注意事项

  • MinerU2.5-Pro 等 OCR 模型需走 /v1/ocr，经 /chat/completions 会返回 400（模型自身限制，非网关 bug）。
  • 飞牛应用中心「列表版本」为缓存展示值；功能版本以 /healthz 为准。
  • 添加账号时若提示 Cannot read properties of null (reading 'value')，请确认所用控制台版本 ≥ 1.0.11（旧版表单字段绑定缺陷已修复）。
