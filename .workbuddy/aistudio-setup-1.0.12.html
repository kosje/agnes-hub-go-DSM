白嫖 Hub · 接入 AI Studio（Mag1cFall/AIStudio2API）

版本 1.0.12 · Windows 端实测指南 · 飞牛端待本机验证后再做

架构结论 必读

Mag1cFall/AIStudio2API 本质是 浏览器自动化代理：靠 Camoufox（Firefox 分支）承载 Google 的 WAA 反自动化运行时，把 AI Studio 网页协议转成 OpenAI 兼容 API。它必须作为独立进程（sidecar）常驻，不能编译进白嫖 Hub 的 Go 进程。

因此集成方式是 sidecar 模式：白嫖 Hub 把它的 OpenAI 端点当作一个上游（与 openrouter 同模式）。白嫖 Hub 负责统一入口、RPM 限流、粘性会话、账号优先级；Mag1cFall 负责真正和 Google 对话。

已用 mock sidecar 在 Windows 端做端到端冒烟测试：客户端 → 白嫖 Hub（Windows exe）→ aistudio 账号 → 转发到 sidecar POST /v1/chat/completions（带 Authorization: Bearer）→ 回传 OpenAI 格式完成体，链路 FORWARD_OK。

① 准备 Mag1cFall sidecar（Windows）

1
下载单文件 Go 二进制 aistudio2api.exe（Releases 页）放到一个目录，例如 D:\ai\aistudio2api\。
2
安装 Camoufox 浏览器运行时（Mag1cFall 的文档里给了一键下载/安装命令；首次需它拉取 Firefox 系运行库）。
3
准备 .env（与 exe 同目录）：
LISTEN_ADDR=127.0.0.1:2048
PROXY_API_KEY=你自定义的sidecar密钥
AISTUDIO_AUTH_STATES=auth
# 可选：HTTPS_PROXY / HTTP_PROXY 让 Camoufox 走代理
4
首次登录 Google 账号（一次性）：运行 ./aistudio2api setup --login，会弹 Camoufox 窗口，登录后认证材料存到 auth/<邮箱>/storage-state.json。之后日常只需双击 exe 即可，无需再登录。
5
启动：直接运行 aistudio2api.exe。确认它监听 http://127.0.0.1:2048/v1/chat/completions。可用 curl http://127.0.0.1:2048/v1/models 验证返回模型列表。
Mag1cFall 默认端口是 2048；若你改了 LISTEN_ADDR，下面白嫖 Hub 里填的 base_url 要同步改。

② 在白嫖 Hub 加 aistudio 账号

打开白嫖 Hub 控制台 http://127.0.0.1:4142/console → 账号 → 添加，填写：

字段值说明
名称AIStudio-01随意
Key你自定义的sidecar密钥必须等于 Mag1cFall 的 PROXY_API_KEY
类型aistudio新增的上游类型；选了它 base_url 自动填 http://127.0.0.1:2048/v1
Base URLhttp://127.0.0.1:2048/v1默认已填，sidecar 在本机/同机时无需改
模型清单（text）gemini-3.8-flash, gemini-3.7-flash, gemini-3.6-flash, gemini-3.1-pro-preview, gemini-3-flash-preview, gemini-2.5-flash, gemini-2.5-pro务必和 Mag1cFall GET /v1/models 返回的真实模型名一致；不一致会路由不到
RPM默认 20（text）保守上限，实测可上调
留空模型清单时，白嫖 Hub 会套用 aistudio 专用默认清单（已内置上述 Gemini 模型），不会再误套 agnes 默认清单。

③ 客户端指向白嫖 Hub

任何 OpenAI 兼容客户端，Base URL 填 http://127.0.0.1:4142/v1，模型填上面声明的 Gemini 名（如 gemini-3.8-flash），Key 填白嫖 Hub 签发的下游密钥。

# 直接打网关验证
curl http://127.0.0.1:4142/v1/chat/completions \
  -H "Authorization: Bearer <白嫖Hub下游Key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"gemini-3.8-flash","messages":[{"role":"user","content":"hi"}],"stream":false}'

请求流：客户端 → 白嫖 Hub（按模型选 aistudio 账号、限流、粘性）→ Mag1cFall sidecar → Google AI Studio。

已知约束 注意

  • Camoufox 必须常驻：sidecar 进程挂了，aistudio 账号全部不可达。这是以后上飞牛的最大门槛（容器内要能跑 Firefox 系运行时）。
  • 至少一次 Google 登录：storage-state.json 过期/失效后需在 Mag1cFall 里重新登录。
  • 内存：每账号 ~700MB+（Camoufox Worker）。
  • WAA 脆弱性：受 Google 反自动化保护，协议可能随时被改，所有同类方案通用风险。
  • 模型名要对齐：白嫖 Hub 的账号模型清单必须和 Mag1cFall /v1/models 完全一致，否则路由不到该账号。

现象可能原因处理
